## 2. 功能清单

**主应用**

- 双分类：「我的一天」/「全部任务」
- 任务字段：名称、截止日期、提醒日期、具体描述（后两者可为空）
- 新建 / 编辑（半模态面板）、勾选完成、滑动删除、加入/移出「我的一天」
- **跨天顺延**：昨天没做完的（手动加入的、已逾期的）今天继续出现在「我的一天」，带「顺延」标记
- 长按拖拽排序（顺序同步到卡片）
- 下拉刷新（自定义旋转箭头 + 松手刷新）
- 完成动画、分段切换方向动画、全屏背景 + 状态栏安全让位
- 提醒设置（早上提醒时间可改）、通知未开启/存储不可用横幅提示

**服务卡片**

- 三种尺寸：`2*2` / `2*4` / `4*4`，纵向滚动列表
- 勾选完成（卡片内直接生效）、点击任务进应用详情、点 `＋` 拉起应用新建页（保存后自动返回桌面）
- 点空白进应用「我的一天」
- 应用内任何变更 → 卡片即时刷新

**提醒**

- 代理提醒（日历型）：截止当天早上（默认 08:00）+ 截止前 10 分钟
- 单应用 30 条上限 → 预算 28 条 + 增量对账（账本记录签名与 id，签名不变不重发）

## 3. 技术架构

```
┌─────────────────────────────┐        ┌──────────────────────────────┐
│ 主应用进程 (UIAbility)       │        │ 卡片提供方进程 (FormExtAbility)│
│  pages/Index.ets            │        │  TodoFormAbility.ets         │
│   ├ TaskRow                 │        │   └ onFormEvent → 写库 → 回推 │
│   └ TaskEditorSheet         │        │                              │
│  EntryAbility（全屏/安全区）  │        │  widget/pages/MyDayCard.ets  │
└──────────┬──────────────────┘        └───────────▲──────────────────┘
           │ 写                                      │ 读
           ▼                                        │
   ┌────────────────────────────────────────────────────┐
   │ data/TaskStore.ets   GSKV Preferences（跨进程安全）  │
   │   task:<id> / meta:version / reminder:* / setting:* │
   │ data/TaskRepository.ets   业务读写 + 排序(order)     │
   └───────────────────────┬────────────────────────────┘
                           │
         ┌─────────────────┴─────────────────┐
         ▼                                   ▼
 service/MyDayService.ets            service/ReminderScheduler.ets
 （纯函数：scope/stats/items/move）    （代理提醒预算与对账）
         │
         ▼
 service/FormBridge.ets（快照构建 + 直推 updateForm）
```

**分层职责**

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 模型/工具 | `common/{Models,TimeUtil,Logger,AppConfig}` | 数据结构与序列化容错、日期归一化、日志、常量 |
| 存储 | `data/TaskStore` | GSKV 读写、版本号缓存、**读写均返回拷贝** |
| 仓储 | `data/TaskRepository` | 增删改、完成切换、拖拽重排、`order` 分配 |
| 领域 | `service/MyDayService` | 「我的一天」归属/计数/列表/拖拽移动（**纯函数，可单测**） |
| 系统集成 | `service/ReminderScheduler`、`service/FormBridge` | 代理提醒排期对账、卡片快照推送 |
| 动效 | `common/Motion.ets` | 统一时长/曲线/过渡/阴影；卡片只用常量（form 应用禁用 `animateTo`） |
| 界面 | `pages/*`、`widget/pages/*`、`entry*Ability` | 列表/面板/卡片/启动参数 |

**数据流（v1.1 重构后）**：所有写操作只在 `TaskRepository` 落库 → `notify(reason)` → 页面监听器统一走 `refresh(animate)`（重算界面 → 推卡片 → 对账提醒）。调用方不再需要"改完记得刷新"，`reason` 决定是否播动画（`create/toggle/delete` 播；`update/order/external` 不播，避免编辑时看起来像被删除）。

## 4. 关键技术决策

| # | 问题 | 决策 | 依据 |
| --- | --- | --- | --- |
| 1 | 卡片与应用是两个进程，存储必须跨进程安全 | 选 **GSKV 模式 Preferences**（API 18+），每任务一个 key | 官方仅对 GSKV 明确"支持多进程并发读写"；XML 模式官方明确"不支持多进程"，RDB 文档则未背书且有"不同 Context 多个库"的坑 |
| 2 | 卡片刷新慢 | 直接 `getPublishedRunningFormInfos()` 拿 formId → 逐张 `updateForm` **直推**，失败才退回 `reloadAllForms` | 后者要经 FMS 拉起卡片进程，链路长 |
| 3 | 「我的一天」自动归类 | **读取时派生**，不落库、不用后台任务 | `workScheduler` 不精准（2h/4h/24h 按活跃度调度），卡片定点刷新只在可见时触发 |
| 4 | 未完成任务跨天消失 | 规则化顺延：`inScope` 六条优先级（今日移出 > 今日手动加入 > 今日到期 > 逾期未完成 > 往期未完成 > 今日完成仅计数） | 纯函数实现，改动只在一处；33 条单测覆盖边界 |
| 5 | 代理提醒 30 条上限 | 预算 28 + 账本增量对账（签名 = kind@时间@标题） | 避免 cancelAll 抖动，避免超限静默丢弃 |
| 6 | 卡片里做动画 | 卡片禁用 `animateTo`/`setTimeout`/`getUIContext`，改用 `.animation()` 隐式动画 + 快照驱动删除 | 三者是 **form 应用的编译期错误**，不是运行时限制 |

## 5. 平台约束（实测/查证结论）

| 约束 | 结论 |
| --- | --- |
| 卡片 UI 能力 | `List`/`Swiper`/`Grid`/`Checkbox` 可用；**`Scroll`/`TextInput`/`DatePicker`/`TimePicker` 不可用**（SDK `@form` 标记为 0）→ 卡片内无法输入，日期选择必须回应用 |
| 卡片手势 | 不支持左右滑动控件（与桌面翻页冲突）→ 列表只能纵向 |
| 卡片数据 | 只能经 `LocalStorageProp` 下发，且会被转成 `string` |
| 卡片进程生命周期 | 回调结束后约 **10 秒**退出 → 卡片侧只做单条读写 |
| 刷新配额 | 定时刷新 **50 次/天/卡片**（0 点重置）；`setFormNextRefreshTime` 最短 5 分钟；定点刷新最多 24 个时间点；卡片不可见时不触发 |
| 代理提醒 | 单应用 **30 条**；权限 `PUBLISH_AGENT_REMINDER` 为 normal + system_grant（**无需 ACL**），但必须先拿通知授权 |
| 全屏与安全区 | `setWindowLayoutFullScreen(true)` 后**框架不自动避让状态栏**，需自行 `getWindowAvoidArea(TYPE_SYSTEM)` 量高度 |

## 7. 迭代中修掉的问题（按根因归类）

| 根因类别 | 典型问题 | 说明 |
| --- | --- | --- |
| **缺少"写入→刷新"统一通道** | 新建后列表不刷新、卡片不更新 | 每个写操作靠调用方手动调 `afterDataChanged`，`save()` 漏调 |
| **列表行刷新契约** | 「全部任务」取消完成不显示 | `ForEach` key 曾简化为纯 `id`，内容变化不重建行；`@Builder` 按值传参同样不刷新 |
| **平台 API 选型错误** | 拖拽无实时让路 | 先用了 `Repeat` 才有的 `onMove`，List 上没有 |
| **卡片能力边界** | 卡片动画/定时器 | `animateTo`/`setTimeout` 在 form 应用里编译期报错 |
| **计数口径** | 显示 `1/0` | total 只算未完成、done 却统计"今天所有完成" |
| **安全区处理** | 内容压到状态栏 | 以为框架会自动避让，实际不会 |
| **视觉细节** | FAB 加号不居中、拖拽时整行左甩 | 全角字符字形偏移；行级 transition 在换位时被误触发 |

## 8. 已知限制

1. **跨进程一致性**：卡片改了数据，应用只在回前台/下拉刷新时同步（无跨进程变更通知；`dataShare` 非官方推荐且需额外 Extension）。
2. **提醒预算**：任务多时只有最近的提醒会被排上，界面没有"哪些任务没排上"的提示。
3. **提醒重入**：进程内已加闸门，但两个进程同时触发对账仍有极小概率重复发布。
4. **拖拽与下拉刷新**：列表顶部向下拖任务时存在手势竞争，未做互斥。
5. **空列表不能下拉刷新**（`Refresh` 需要可滚动子组件）。
6. **卡片离场动画依赖快照回推**：推送失败时该行会停在 15% 透明（可点，下次刷新自愈）。
7. **无数据迁移机制**：字段增删靠 `fromJson` 默认值兜底，没做 schema 版本。

## 9. 后续建议（按优先级）

1. **Repository 变更事件**（消除"忘记刷新"这一类 bug，目前是最大技术债）。
2. 提醒裁剪的用户提示 + 超额时的策略说明。
3. 拖拽/下拉刷新手势互斥；空态支持下拉。
4. 数据导出/备份（`EntryBackupAbility` 已存在但未接业务）。
5. 卡片尺寸增加 `1*2`（当前 `2*2 / 2*4 / 4*4`）。
